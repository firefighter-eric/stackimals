# Stackimals 发布检查清单

本清单适用于合并到 `main` 和发布到 Vercel Production。文档或纯注释改动可按风险缩小运行时验收，但仍需检查链接、格式和部署状态。

清单中的方框是门禁，不是结果描述。失败项不能勾成通过；纯文档等不适用项应在发布记录中标为 `N/A` 并说明原因。若产品负责人明确接受临时豁免，必须记录缺陷、风险、适用版本和后续处理计划，同时保留该项未通过状态。

## 1. 范围与工作区

- [ ] 变更范围与[产品要求](./PRODUCT_REQUIREMENTS.md)一致，没有顺带加入当前不做的能力。
- [ ] `git status --short` 已审查；没有混入无关、临时、调试或本机文件。
- [ ] 新行为有需求编号或明确的缺陷说明。
- [ ] 玩法、边界、资源、AI 或部署发生变化时，对应 `doc/` 文档已同步。
- [ ] 没有提交 `.env*`、`.vercel/`、日志、截图报告、测试产物或凭据。

## 2. 自动化检查

使用 Node.js `>=22.12.0` 和 pnpm `10.17.1`，先按锁文件安装，再在项目根目录运行：

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
```

- [ ] TypeScript 无错误。
- [ ] Vitest 全部通过；当前基线为 11 个测试文件、44 个测试。
- [ ] Vite Production build 成功，输出目录为 `dist/`。
- [ ] 新增 warning 已解释；不能把 build warning 当作 build 成功的替代，也不能把既有大 chunk warning误报为编译失败。
- [ ] `git diff --check` 无空白错误。

## 3. 规则与状态回归

- [ ] 首次加载后是玩家第 1 回合，双方 0 分。
- [ ] 玩家可拖动、旋转和投放；投放后控制立即禁用。
- [ ] 玩家成功稳定后只给玩家加分并切到 AI。
- [ ] AI 成功稳定后只给 AI 加分、回合数加一并切回玩家。
- [ ] 当前动物直接掉落时，当前投放者失败。
- [ ] 当前投放撞落旧动物时，仍由当前投放者失败。
- [ ] 换手后、下一方尚未投放前发生的延迟掉落，不会被错误归责给下一方；当前基线对此有已知缺口。
- [ ] 稳定后越过危险线时，当前投放者失败。
- [ ] 持续不稳定到超时时，游戏结束而不是永久卡住。
- [ ] 游戏结束后没有继续移动、计分、换手或 AI 投放。
- [ ] 玩家与 AI 各有 3 次独立换动物机会；次数耗尽后不能继续换。

## 4. 碰撞和物理回归

- [ ] 十五只动物均保持源 WebP 宽高比，没有压扁或拉长。
- [ ] 开发环境使用 `?debugPhysics` 检查轮廓贴合可见边缘和旋转原点。
- [ ] 平台、动物之间没有明显悬空、稳定穿模或透明区域假碰撞。
- [ ] 至少检查一只宽动物、一只高动物和一只不规则动物的多种角度。
- [ ] 新增或替换动物后，WebP 尺寸、alpha bounds、outline、texture origin 和物理参数均已更新。
- [ ] 玩家和 AI 在所有允许角度下，真实碰撞轮廓都留在 `x = 34…356`；当前 AI origin 裁剪对此有已知缺口。
- [ ] 低帧率或浏览器切后台再返回时，没有一次性大步进导致动物穿透或飞出。

`src/test/colliderRegression.test.ts` 的数值阈值是最低自动化门槛，不替代视觉检查。

## 5. 输入、暂停和重开

- [ ] 触屏拖动坐标与手指一致，Canvas 缩放或 DPR 改变后没有偏移。
- [ ] 两个旋转按钮和投放按钮只在玩家瞄准阶段可用。
- [ ] `A/D`、方向键、`Q/E`、`R`、`Space/Enter` 行为正确，且焦点在文本输入或可编辑区域时不会劫持输入。
- [ ] `P` / `Esc` 在游戏区域和游戏/模态按钮聚焦时均符合暂停、继续或取消契约。
- [ ] 窗口失焦或松键后，没有残留持续移动。
- [ ] 暂停会冻结动物、AI 思考计时和 Tween；继续后只恢复一次。
- [ ] AI 思考或动画期间暂停、重开，不会在新局产生旧 AI 的幽灵投放。
- [ ] 连续多次重开后只有一个 Canvas、一个 Phaser 实例和一组输入监听器。
- [ ] 重开确认框的“返回”和“重新开始”都可用，`Esc` 可关闭确认框。
- [ ] 辅助线首次使用默认关闭；在暂停设置中开启后，危险横线、落点竖线和落点框同时出现，关闭后同时消失，刷新后保留用户选择。
- [ ] 当前基线的模态焦点键盘缺口已修复，或存在产品负责人明确记录的临时豁免；该项不能因“已知”而被勾成通过。

## 6. UI、设备和可访问性

至少检查以下视口：

- [ ] 当前最小支持视口 `320 × 568`。
- [ ] `390 × 844` 或相近的主流竖屏手机。
- [ ] 带顶部/底部安全区的真实 iPhone Safari。
- [ ] Android Chrome 竖屏。
- [ ] 高度不超过 `520px` 的移动设备横屏，显示竖屏提示。
- [ ] iPad 横屏和 16:9 桌面窗口使用顶部居中 HUD、全宽游戏区域且没有固定左侧栏。

所有视口还需确认：

- [ ] HUD、当前动物提示、平台和底部控制均可见；开启辅助线后危险横线、落点竖线和落点框均可见。
- [ ] 页面不滚动、不横向溢出，浏览器动态地址栏不遮住关键按钮。
- [ ] 焦点环可见；按钮具有正确可读名称和 disabled 状态。
- [ ] 模态打开后检查焦点范围、背景交互和关闭后的焦点恢复；当前仅有基础 ARIA 语义时不得宣称完整无障碍。
- [ ] 阶段提示、暂停、错误和结果文案与真实状态一致。
- [ ] 模拟启动或资源加载失败时，错误入口能够实际重新创建游戏，而不是只显示按钮或把命令永久排队；当前基线对此有已知缺口。
- [ ] `prefers-reduced-motion` 下没有非必要的持续动画。
- [ ] 页面缩放策略经过检查；当前 `user-scalable=no` 是已知可访问性缺口。
- [ ] 浏览器拒绝或尚未解锁音频时，游戏仍能完整游玩。

- [ ] 确认发布的是预期 commit，Production 状态为 Ready。

- [ ] 记录 Production URL、commit、自动化结果、真机/浏览器覆盖和未解决限制。

## 10. 回滚条件

出现以下任一情况，应停止推广或回滚到上一个已验证 Production：

- 页面无法加载、持续白屏或资源批量 404。
- 玩家无法投放、AI 不再行动、回合永久卡住或胜负明显错误。
- 动物显著压缩、拉伸、悬空、稳定重叠或频繁穿透平台。
- 暂停/重开造成重复 Canvas、重复监听器或幽灵 AI 操作。
- 移动端关键按钮被安全区或浏览器 UI 遮挡。
- Production 意外暴露测试 API、凭据或未经说明的数据上传。

回滚后保留失败部署和日志作为证据，修复必须重新走本清单，不能只以本地 build 成功作为完成依据。
