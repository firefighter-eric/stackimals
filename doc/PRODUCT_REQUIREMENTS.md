## 2. 产品定义

Stackimals 是一款 2D 物理堆叠游戏。玩家与友好的 Milo AI 轮流选择水平落点、旋转并投放一只动物积木。每次投放都必须等待整个动物塔稳定；谁的操作造成动物掉出场外、动物塔越过危险线，或长时间无法稳定，谁就输掉本局。

核心体验是“看起来简单、由不规则边缘产生策略”的短局游戏。动物的可见轮廓必须与物理碰撞轮廓一致，玩家应能根据画面判断接触点和平衡，而不是被不可见矩形或明显穿模欺骗。

## 3. 产品目标

1. 在打开页面后直接进入一局完整、可重复游玩的玩家对 AI 游戏。
2. 在手机竖屏上用单手完成拖动、旋转、投放、暂停和重开。
3. 让十五种动物因尺寸、轮廓、重量和姿态产生可感知的堆叠差异。
4. 保持规则可解释：失败必须能归因到当前投放者和明确原因。
5. 无需登录、下载或后端即可在 Vercel 静态站点运行。

## 4. 当前不做

- 在线实时 PvP、同屏双人和匹配系统。
- 账号、云存档、排行榜、成就、付费和广告。
- 关卡、剧情、道具、技能或有限生命系统。
- 3D 渲染、Three.js、React Three Fiber 或 3D 模型资产。
- 服务器权威物理、反作弊和跨设备回放。
- 安装型 PWA、离线缓存和推送通知。

以上能力如果进入路线图，必须先修改本文档和[边界条件](./BOUNDARIES_AND_NOTES.md)，不能作为普通 UI 或物理修复的隐含范围。

## 5. 术语

- **回合（round）**：玩家投放一次并稳定、随后 AI 投放一次并稳定，构成一个完整回合。AI 成功稳定后，回合数加一。
- **轮次（turn）**：玩家或 AI 的单次投放机会。
- **当前投放者**：触发本次下落与结算窗口的一方。其操作引发的所有连锁掉落都由其负责。
- **稳定**：所有在场动物的线速度和角速度连续满足稳定阈值，而不是仅等待固定时长。
- **危险线**：场内红色虚线。动物塔稳定后，任一动物的物理边界越过该线即判当前投放者失败。
- **出界**：动物的物理边界整体越过指定的底部或水平缓冲区。

## 6. 一局游戏的完整流程

1. 页面加载 React 界面和 Phaser 资源；加载成功后由玩家先手。
2. 玩家获得一只当前动物。玩家可拖动选择水平落点、连续旋转，并可消耗本局换动物次数替换当前动物。
3. 玩家点击或按键投放后，控制立即锁定，动物进入 Matter 物理世界。
4. 在本次 `dropping/settling` 结算窗口中，首次 `collisionstart` 记录接触；每次更新检查出界、运动状态和稳定超时；只有确认稳定后才检查危险线。
5. 若玩家投放成功稳定，玩家分数加一，进入 AI 轮次。
6. AI 根据当前动物塔生成候选位置和允许角度，展示移动过程后投放；最终结果仍由同一个 Matter 世界裁决。
7. 若 AI 投放成功稳定，AI 分数加一，回合数加一，进入下一次玩家轮次。
8. 任一方触发失败条件后，物理世界暂停并显示胜负、原因和本局比分。
9. 玩家可选择再来一局；重开会清空动物塔、比分和回合状态。

本版本没有目标分数或最大回合数。一局会持续到某一方失败。

## 7. 玩法要求

| 编号 | 优先级 | 当前要求 | 验收结果 |
| --- | --- | --- | --- |
| PRD-GAME-001 | P0 | 玩家必须先手，玩家与 AI 严格交替投放。 | 任一方成功稳定后只能切换到另一方；游戏结束后不能再产生新轮次。 |
| PRD-GAME-002 | P0 | 玩家只能在自己的瞄准阶段移动、旋转或投放。 | 加载、下落、稳定、AI、暂停、结束和错误阶段的玩法控制均禁用。 |
| PRD-GAME-003 | P0 | 拖动和连续左右移动都必须按动物旋转后的碰撞轮廓限制在合法水平区域内。 | 动物预览的真实碰撞轮廓不会被放到左右边界之外。 |
| PRD-GAME-004 | P0 | 玩家可围绕动物中心连续旋转；AI 使用动物定义中的离散候选角度。 | 按住 UI 或键盘旋转键时角度连续变化，AI 仍只提交合法候选姿态。 |
| PRD-GAME-005 | P0 | 投放后必须由真实物理结算，不允许把最终位置直接吸附或写死。 | 分数与换手只在物理稳定后发生。 |
| PRD-GAME-006 | P0 | 当前投放造成任意动物掉出场外时，当前投放者失败；被撞掉的是旧动物或对手动物也不改变责任。 | 连锁掉落的胜负归因稳定且可由规则测试复现。 |
| PRD-GAME-007 | P0 | 动物长时间无法稳定时，当前投放者失败，游戏不能无限卡在结算状态。 | 超过稳定等待上限后进入结束状态并显示原因。 |
| PRD-GAME-008 | P0 | 动物塔稳定后，任一物理边界越过危险线时，当前投放者失败。 | 预览动物和仍在运动的瞬时越线不提前结算；稳定后检查整座塔。 |
| PRD-GAME-009 | P0 | 每次成功稳定只给当前投放者加一分。 | 玩家成功后仅玩家分数加一；AI 成功后仅 AI 分数加一。 |
| PRD-GAME-010 | P1 | 玩家与 AI 各自使用独立的十五动物洗牌袋。 | 每个完整袋包含十五种动物各一次，跨袋边界尽量避免连续相同动物。 |
| PRD-GAME-011 | P1 | HUD 必须分别显示双方接下来的三只动物。 | 预览队列不消耗真实队列，不改变后续顺序。 |
| PRD-GAME-012 | P0 | AI 必须使用相同的动物集合、允许角度、数值场地范围和 Matter 物理裁决。 | AI 不能直接提交最终稳定位置或绕过失败检查；候选位置的边界算法差异记录在工程边界中。 |
| PRD-GAME-013 | P0 | 暂停必须冻结物理、AI 计时和动画；继续后从原状态恢复。 | 暂停期间无掉落、换手、加分或幽灵 AI 投放。 |
| PRD-GAME-014 | P0 | 重开必须取消旧 AI 工作并清空本局状态。 | 重开后为第 1 回合、双方 0 分、玩家先手，旧计时器不能影响新局。 |
| PRD-GAME-015 | P0 | 动物视觉比例必须保持源图比例，物理轮廓必须贴合可见边缘。 | 稳定状态不能出现明显重叠、悬空或由大面积透明区域造成的假接触。 |
| PRD-GAME-016 | P0 | 上一次投放的延迟后果不能归责给尚未投放的下一方。 | 从换手到下一方实际释放动物之前发生的旧动物掉落，仍应归责给上一投放者，或在换手前完成结算。 |
| PRD-GAME-017 | P1 | 玩家与 AI 每局各有 3 次换动物机会，双方计数互不影响。 | 换动物会立即替换当前预览并推进自己的队列；次数归零后不可继续换。 |
| PRD-GAME-018 | P1 | 桌面模式显示桌子两侧的玩家代表动物和 Milo 代表动物。 | 玩家可在设置中选择代表动物；Milo 的代表动物不能与玩家相同。 |
| PRD-GAME-019 | P1 | 危险高度与落点辅助线默认关闭，并可在暂停设置中统一开启。 | 开关同时控制危险横线、落点竖线和落点框；视觉隐藏不改变危险线判定，用户选择保存在本地浏览器。 |

## 8. 动物内容

当前动物共十五种：小熊、小鸟、小猫、鳄鱼、大象、小狐狸、青蛙、长颈鹿、小刺猬、小鼠、企鹅、小兔、小浣熊、老虎和小龟。

每只动物必须定义：

- 唯一 ID、中英文名称和运行时资源路径。
- 原图尺寸与保持原比例的逻辑显示尺寸。
- 独立的密度、动摩擦、静摩擦、弹性和空气阻力。
- 允许旋转角度列表。
- 与透明图可见边缘对齐的碰撞轮廓及纹理原点。

新增或替换动物时，不允许只替换图片。完整流程见[资源与碰撞边界](./BOUNDARIES_AND_NOTES.md#5-动物资源与碰撞边界)。

## 9. 界面和输入要求

### 9.1 HUD

HUD 必须持续显示：

- 当前回合数。
- 玩家和 Milo 的已成功投放数量。
- 当前行动方及清晰的视觉状态。
- 双方后续三只动物。
- 当前动物、当前行动方和阶段提示。
- 双方剩余换动物次数。
- 可用的暂停入口。

### 9.2 触屏

- 在游戏区域按下或拖动，改变当前动物的水平落点。
- 按住底部左右按钮分别连续向左、向右旋转。
- 当前动物提示提供换动物按钮，每局最多使用 3 次。
- 底部主按钮执行投放。
- 只在玩家瞄准阶段响应玩法输入。

### 9.3 键盘

- `A` / `D` 或 `←` / `→`：按住连续左右移动。
- 按住 `Q` / `E` 或 `↓` / `↑`：连续向左或向右旋转。
- `R`：换动物。
- `Space` / `Enter`：投放。
- `P` / `Esc`：暂停或继续；打开重开确认时，关闭确认框。

移动、旋转和投放快捷键不得劫持文本表单或可编辑区域中的输入。`P` / `Esc` 是游戏级暂停/取消快捷键，在焦点位于游戏按钮或模态按钮时仍应生效；如果未来加入文本输入或可编辑区域，则不应劫持其中的按键。窗口失焦时必须释放持续移动与旋转状态。

### 9.4 暂停、重开和结果

- 暂停界面提供“继续游戏”和“重新开始”。
- 暂停设置提供语言、玩家代表动物和辅助线选项；辅助线首次使用默认关闭。
- 重开必须二次确认，并说明动物塔和分数会清空。
- 结束界面显示赢家、失败原因、双方分数和“再来一局”。
- 资源或启动失败时显示明确错误，并提供能够重新创建游戏实例的恢复入口，而不是保留无响应的空画布。

## 10. 体验和质量验收

### 10.1 必须通过

- 从首次加载到多次重开的完整流程无需刷新页面。
- 玩家和 AI 均可因直接掉落、连锁掉落、越过危险线或超时而正确失败。
- 暂停和重开不会留下旧输入、计时器、Tween、Matter 监听器或重复画布。
- 在目标竖屏尺寸下 HUD、画布、提示和控制区均可见且不产生页面滚动。
- 动物保持原图比例；碰撞轮廓、纹理原点和可见 alpha 一致。
- 全部适用的自动化检查以及[发布检查清单](./RELEASE_CHECKLIST.md)通过；任何临时豁免都必须由产品负责人明确接受并记录，不能把失败项勾成通过。

### 10.2 产品质量原则

- 视觉结果优先于“物理参数看起来合理”：若动物稳定后明显陷入、悬空或抖动，应视为缺陷。
- AI 可以不是最优解，但必须可理解、合法且受相同规则约束。
- 阶段提示必须与当前真实状态一致，不能在控制已锁定时仍提示玩家操作。
- 失败原因必须使用玩家可理解的文案，不直接暴露 Matter、AABB 或内部状态名。

### 10.3 当前实现偏差

以下项目是已确认差距，不能因为要求已写入本文档就宣称完成：

- 模态已有 ARIA dialog 语义，但尚无完整 focus trap、背景 `inert` 和关闭后的焦点恢复。
- 移动短横屏的竖屏提示只是视觉遮罩，不会同步暂停 Matter、AI 计时或全局键盘输入。
- 触摸横向移动依赖 Canvas 拖动，没有等价的 DOM 左右移动控件。
- 页面当前设置 `user-scalable=no`，不满足允许低视力用户缩放页面的更高可访问性目标。
- 错误 UI 能展示同步 mount 异常，但资源加载没有失败监听；Scene 尚未创建时，“再试一次”只会排队 `restart` 命令，不能保证重新 mount，因此不满足完整的可恢复错误契约。
- 出界和稳定结算只在 `dropping/settling` 执行；若旧动物在玩家瞄准或 AI 思考阶段才完全出界，当前不会立即结算，下一次投放开始后还有被错误归责给下一投放者的风险。
- AI 以旋转后显示矩形和中心点裁剪候选位置，但实际 sprite/body 使用非中心 `textureOrigin`；真实碰撞轮廓因此可能轻微越过 `34…356`，尚未完全满足与玩家一致的合法边界要求。

这些偏差应进入后续修复，不应在文档任务中被静默改写为“设计如此”。
